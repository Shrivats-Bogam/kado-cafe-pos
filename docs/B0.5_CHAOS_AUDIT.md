## 2. Defects Identified & Resolved During B0.5 Audit

During initial chaos harness execution, 2 code defects were uncovered and immediately remediated prior to final release validation:

### Bug 1: Uncaught `ReferenceError: Cannot access 'update' before initialization`
- **Category**: Initialization Order / Temporal Dead Zone
- **Root Cause**: `StaffApp.jsx` declared `const update = (apply) => ...` below line 210, but `LoginScreen` handler at line 200 called `update(...)` during user login, placing `update` in the TDZ during session mount.
- **Fix**: Moved `const update = (apply) => setStateRaw((prev) => apply(prev));` above line 185, ensuring initialization prior to any rendering guard.
- **Verification**: Verified zero uncaught console errors in `TEST-ERR-01`.

### Bug 2: Zero-Cash Payment Allowed on Cash Checkout
- **Category**: Payment Chaos / Validation Boundary
- **Root Cause**: In `BillModal.jsx`, `isCashUnderpaid` evaluated `cashNum > 0 && cashNum < finalTotal`. When cash received input was empty or `0`, `isCashUnderpaid` returned `false`, enabling `confirm-payment-btn`.
- **Fix**: Updated `isCashUnderpaid = paymentMode === "Cash" && cashNum < finalTotal`. When cash received is `< finalTotal` (including 0 or empty), `isCashUnderpaid` is `true`, disabling payment confirmation.
- **Verification**: Verified by `TEST-PAY-02`.

### Bug 3: Pending Bill Status & Premature Stock Deduction
- **Category**: Billing Action Logic
- **Root Cause**: In `src/state/actions.js`, `generateBillForTable` hardcoded `status: "Paid"` and immediately deducted inventory stock even when `paymentMode === "Pending"`.
- **Fix**: Updated `generateBillForTable` to check `const isPending = paymentMode === "Pending"`. When pending, `status` is set to `"PENDING"`, `paidAt` to `null`, and inventory stock deduction is deferred until conversion to `Paid`.
- **Verification**: Verified by `TEST-PEND-01`.
