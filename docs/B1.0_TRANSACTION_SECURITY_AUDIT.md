## 1. Architecture Before B1.0
Prior to B1.0, financial totals, bill amounts, and stock deductions were computed in client-side React reducers (`src/state/actions.js`) and pushed as raw JSON blobs to Supabase `cafe_state`. While client-side idempotency guards prevented UI multi-click errors, an adversarial client could tamper with bill totals, refund amounts, or inventory deduction values before saving.

## 2. Security Problems Discovered & Mitigated
- **Client-Authoritative Bill Settlement**: Resolved. Database now looks up ground truth grand totals in `pos_orders`.
- **Client-Authoritative Refunds**: Resolved. Database validates paid amounts and previous refund totals.
- **Client-Authoritative Stock Deduction**: Resolved. Database checks `pos_recipes` and enforces `orderRef` idempotency.
- **Unconfirmed Offline Payments**: Resolved. Unconfirmed offline payment attempts return status `PENDING_SERVER_CONFIRMATION` instead of claiming payment succeeded.

## 3. Database Schema Changes & RPC Functions
Created [`supabase/b10_server_transactions.sql`](file:///C:/Users/Admin/.gemini/antigravity/worktrees/kado-cafe/redesign_tables_pos_ui/supabase/b10_server_transactions.sql):
- `pos_financial_ledger`: Immutable financial ledger tracking `SALE`, `PAYMENT`, `REFUND`, `DISCOUNT`, `EXPENSE`, and `ADJUSTMENT`.
- `pos_refunds`: Relational table tracking refund IDs, reasons, and amounts.
- `pos_idempotency_keys`: Unique key constraint table storing transaction result JSON blobs.
- **RPC 1 (`settle_payment_transaction`)**: Atomic payment settlement locking `pos_orders` for update, validating caller role, checking idempotency, enforcing DB authoritative bill total, recording ledger entry, performing recipe stock deduction, logging audit event, and executing full `ROLLBACK` on error.
- **RPC 2 (`settle_split_payment_transaction`)**: Validates `SUM(split_amounts) == DB_authoritative_total`, rejecting underpayments, overpayments, zero, and negative amounts.
- **RPC 3 (`process_refund_transaction`)**: Validates `Owner`/`Manager` permissions, checks previous refund sums, creates negative ledger entries, updates order status to `'REFUNDED'`.

## 4. RLS & Tenant Isolation
Enforced database-level Row Level Security policies across `pos_financial_ledger`, `pos_refunds`, and `pos_idempotency_keys` using `organization_id = auth.current_organization_id()`.
